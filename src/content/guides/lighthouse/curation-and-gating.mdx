Family members don't get raw ComfyUI — they get a **curated set of workflows** scoped to their role, with maturity and tier gating enforced at the proxy (`06`). This stage covers what to curate, how the node allowlist derives from it, and a worked base workflow.

## Curation strategy (the decision)

A **small set of clean, core-node base workflows** + a **vetted handful of shared custom nodes** — NOT community mega-workflows (every custom node is §7-allowlist surface + arbitrary-code risk). Base graphs are **DistributedCollector + DistributedSeed wrapped** so they fan out to the GPU fleet (without the collector, the master CPU-renders — `11-C1`).

**Base workflows:** standard-SDXL + HiRes-fix (core nodes only), an Illustrious/booru base, a photoreal base, and an img2img+ControlNet "restyle". **Approved custom-node packs (each vetted, pinned, symmetric-installed):** Impact-Pack FaceDetailer/SAMLoader/UltralyticsDetectorProvider, Ultimate SD Upscale, ControlNet-aux (canny+depth), IPAdapter. **Excluded:** FaceID/faceswap, embeds save/load, arbitrary-dispatch preprocessors (`phase2a-vetted-node-packs` for the full pin/exclude list + mitigations).

## How the §7 allowlist relates to curation

The licence-gate's node allowlist (`allowlist.json`, a configmap — `11-P5`) is the **union of node class_types across the curated workflows**. Add a curated workflow that uses a new node → add that class_type to the allowlist → redeploy the config. Add a curated custom-node pack → add its execution class_types (e.g. `FaceDetailer`, `UltimateSDUpscale`, `IPAdapter`, `CannyEdgePreprocessor`, `DepthAnythingV2Preprocessor`) as `{}` (execution-only). The licence-gate already treats `IPAdapterModelLoader`/`LoraLoader`/etc. as *model loaders* (they carry `model_fields`) so their models role/licence-gate; the new processing nodes are execution-only. **Never** allowlist model-writer savers or arbitrary-dispatch nodes.

## A worked base workflow (proven end-to-end through the gate)

Standard SDXL + HiRes-fix (core nodes; only `LatentUpscaleBy` is "new" vs a vanilla txt2img). Submitted to `/distributed/queue`, it passed the gate, dispatched to two heavy workers, and produced a 1536² image in the caller's per-user bucket:

```json
{ "client_id":"smoke-hires", "enabled_worker_ids":["gpu-worker-1","gpu-worker-2"], "delegate_master":true,
  "prompt": {
    "4":{"class_type":"CheckpointLoaderSimple","inputs":{"ckpt_name":"sd_xl_base_1.0.safetensors"}},
    "6":{"class_type":"CLIPTextEncode","inputs":{"text":"<positive>","clip":["4",1]}},
    "7":{"class_type":"CLIPTextEncode","inputs":{"text":"<negative>","clip":["4",1]}},
    "5":{"class_type":"EmptyLatentImage","inputs":{"width":1024,"height":1024,"batch_size":1}},
    "3":{"class_type":"KSampler","inputs":{"seed":42,"steps":20,"cfg":7.0,"sampler_name":"euler","scheduler":"normal","denoise":1.0,"model":["4",0],"positive":["6",0],"negative":["7",0],"latent_image":["5",0]}},
    "11":{"class_type":"LatentUpscaleBy","inputs":{"samples":["3",0],"upscale_method":"nearest-exact","scale_by":1.5}},
    "12":{"class_type":"KSampler","inputs":{"seed":42,"steps":20,"cfg":7.0,"sampler_name":"euler","scheduler":"normal","denoise":0.45,"model":["4",0],"positive":["6",0],"negative":["7",0],"latent_image":["11",0]}},
    "8":{"class_type":"VAEDecode","inputs":{"samples":["12",0],"vae":["4",2]}},
    "10":{"class_type":"DistributedCollector","inputs":{"images":["8",0],"load_balance":false}},
    "9":{"class_type":"SaveImage","inputs":{"filename_prefix":"workshop-hires","images":["10",0]}}

```

The licence-gate rewrites `filename_prefix` → `<user-uuid>/workshop-hires` before dispatch. Note the **two incompatible ComfyUI JSON formats** (`11-C7`): this is `.api.json` (submission); the UI canvas uses `.workflow.json`.

## Role-scoped App Mode surface (the curation seed)

Each curated entry declares `role_allowlist` (App-Mode *visibility*) + `permitted_models`. Two layers, by design:

- **Visibility** (`role_allowlist`) — what shows in a user's App Mode index. UX only; craftable-around.
- **Enforcement** (`requires_group` on the model, in the registry) — the real boundary, at the proxy (`06`).

**Mature content reuse pattern:** the maturity boundary is the *model tag*, not the workflow — so the same base graphs are reused via mature-scoped entries (same template, gated `permitted_models` + `role_allowlist: [mature-content]` + appropriate prompt defaults). No separate mature graphs needed; the quality nodes (FaceDetailer/upscale/ControlNet/IPAdapter) apply to mature work too.

## Known-open caveats (mention, don't sell)

The App Mode UI gallery ("Media Assets → Generated") doesn't currently surface renders (they're on disk; the asset layer isn't wired) — and the Jobs panel + one editor have minor frontend issues. Rendering, gating, isolation, and saving all work; the *browse-your-results* UI is the gap. Don't screenshot the gallery as working.
